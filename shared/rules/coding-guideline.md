# コーディングガイドライン

このファイルは、全プロジェクト共通のコーディングガイドラインを定めるものです。プロジェクトごとに異なるルールがある場合は、プロジェクト固有のガイドラインファイルを参照してください。

## 実装

- 命名・整形・ファイル構成・API 応答形式は、対象プロジェクトの既存規約を優先する。
- 名前で目的を表し、分岐や型を読みやすくする。TypeScript では安易な `any` や型アサーションで不整合を隠さない。
- 外部入力は信頼境界で型・形式・範囲を検証する。型宣言だけを実行時の検証とみなさない。
- HTTP ステータスなど API の失敗条件を確認し、エラーを握りつぶさず原因を保持して適切な呼び出し元へ伝える。
- 非同期処理の失敗を処理し、並列化は処理間に依存や副作用の競合がない場合に限る。
- React の state/props は直接変更せず、前の state に依存する更新には関数形式の updater を使う。

## 命名規則

- コンポーネント: PascalCase
- 関数/変数: camelCase
- 定数: UPPER_SNAKE_CASE
- ファイル: camelCase

## コメント

- 複雑なロジックにのみコメントを書く
- 自明なコードにはコメント不要
- TODO/FIXMEは具体的な内容を記載

## テスト

- コード変更後はテストを実行して確認する
- テストが失敗した場合は修正する

## セキュリティ

- `.env` や認証情報を含むファイルはコミットしない
- 機密情報をコードやコメントに含めない
- APIキーやパスワードはハードコードしない
